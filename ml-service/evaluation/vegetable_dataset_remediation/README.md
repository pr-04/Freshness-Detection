# Vegetable dataset remediation review

Research and manual-review preparation for FreshGuard AI Phase 7. This folder contains audit artifacts only. It does not alter the existing inventory, labels, splits, model or application.

## Files

- `final_report.md` — summary, evidence, readiness decisions and remaining blockers.
- `existing_dataset_reassessment.csv` — category counts and quality/provenance summary recomputed from the prepared inventory.
- `conflicting_label_review.csv` — every image row in each exact-hash group with contradictory Fresh/Rotten labels; original labels and source fields are retained.
- `manual_review_manifest.csv` — all conflict rows plus a small deterministic Fresh/Rotten sample per populated vegetable, including previous spot-review examples. Every entry starts as `Pending`.
- `manual_review_gallery.html` — locally viewable contact sheet with embedded thumbnails and each path, label, hash and review reason.
- `external_dataset_research.csv` — external candidate comparison; counts, label semantics, licensing and uncertainty are recorded separately.
- `onion_dataset_research.md` — onion-specific findings and proposed follow-up.
- `final_readiness_matrix.csv` — category decisions using the requested decision vocabulary.

## How to conduct manual review

1. Open `manual_review_gallery.html` locally in a browser. It contains embedded thumbnails; images in the original dataset are not modified.
2. For each card, inspect the actual produce item and visible evidence. Use a project-approved written rubric that distinguishes normal ripeness, bruising/cosmetic damage, dehydration, mold/rot, and uncertain cases. Do not use a model prediction to assign a label.
3. Review all rows sharing a `CONFLICT-###` group together. The SHA-256 column means identical bytes share a group. Do not resolve by majority vote: decide from the image and source provenance, or retain as unresolved/reject from a later curated subset.
4. Record the human decision in a copied review worksheet or a new, separate file. Do not change `current_label` in this manifest or any source inventory. Include reviewer, date, rationale, confidence/uncertainty and final disposition.
5. For near-duplicate candidates, treat dHash as a triage signal only. Visually compare the actual images and record confirmed identity separately; similar shape/background does not prove duplication.
6. Before any training subset is made, resolve source rights and attribution, then create a new manifest and source/physical-object-aware splits. Keep existing manifests and test data untouched.

## Scope and reproducibility

Inventory summaries were recomputed from `ml-service/datasets/expansion_15/dataset_inventory.csv`; exact duplicates were grouped by SHA-256. Conflicting-label groups were generated by checking whether a single SHA-256 had more than one normalized condition. Candidate sample selection used the first three sorted image hashes per existing vegetable and condition, with existing Phase 11B sample-review images included. No labels were edited, no images downloaded, and no model was trained. External pages were checked read-only on 2026-10-31. Publicly reported external counts/licensing are not independently verified against downloaded archives.
