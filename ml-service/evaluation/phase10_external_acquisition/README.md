# Phase 10 external dataset verification and staging

This workspace records Phase 10 source checks and controlled acquisition status. No external dataset passed all source, class-label, license/provenance and archive metadata gates; **no dataset was downloaded**.

## Deliverables

- `final_report.md` — decision and findings.
- `external_dataset_comparison.csv` — paper/record-reported coverage, clearly separated from archive-verified counts.
- `source_verification.csv` — source accessibility, labels, rights, overlap and acquisition decision.
- `license_and_provenance_report.md` — reuse and attribution limitations.
- `category_coverage.csv` — all target fruits/vegetables and paper-reported counts where available.
- `download_manifest.csv` — explicit `NO DATASETS DOWNLOADED` record; no fake checksums.
- `archive_checksum_report.csv` — generated by the staging checker; no archives found.
- `image_integrity_report.csv` — generated by the staging checker; no external images staged.
- `duplicate_and_overlap_report.csv` — no image-level checks without staged files; metadata risk is summarized separately in the report.
- `final_readiness_matrix.csv` — category decisions using the allowed terms.
- `scripts/verify_staged_data.py` — reproducible archive SHA-256, Pillow validation/dimensions/quality, exact-hash comparison and dHash candidate comparison against the existing inventory.

## Staging

`ml-service/datasets/external_staging/phase10/archives/` and `extracted/` are intentionally empty. The staging README explains why. No archive exceeded or consumed the Phase 10 budget because none was downloaded. The Onion v1 Mendeley archive is reported at 2.25 GB and therefore above the 2 GB per-archive limit; it was not downloaded.

## Re-run safe checks

From project root:

```powershell
python -m pip install Pillow
python ml-service/evaluation/phase10_external_acquisition/scripts/verify_staged_data.py
```

The script reads files only under the Phase 10 staging directory and the existing inventory. It writes reports only to this Phase 10 evaluation directory. It never downloads, extracts, deletes, moves, relabels, or edits images. dHash matches at distance 1–4 are candidates for visual review, never confirmed duplicates.

## Decisions

- Do not use `Good/Bad` as Fresh/Rotten without written definitions.
- Do not use Onion `Healthy/Unhealthy` as Fresh/Rotten.
- Preserve Semi-Fresh as a separate class if AgriFreshNET is considered later.
- Freshness44 and the five-vegetable paper are promising metadata leads, not verified datasets for acquisition; licenses, source image provenance, current archive contents and overlap remain unresolved.
- Any future acquisition requires separate approval of a source that passes all rights and label checks, followed by staging, archive checksum, image integrity, and source-overlap audit. No training or app integration is included here.
